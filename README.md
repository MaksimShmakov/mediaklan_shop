# Медиаклан Маркет

Минималистичный магазин на FastAPI для выдачи товаров за баллы.

## Быстрый старт

1. Скопируйте пример окружения:

```bash
cp .env.example .env
```

2. Задайте в `.env` секреты, пароль администратора и доступы к Postgres.
3. Запустите:

```bash
docker compose up --build
```

Откройте `http://localhost:8000`.

## Как пользоваться

- Вход пользователей: `/login`.
- Админ-панель: `/admin/login`.
- В админ-панели настраиваются:
  - окна работы магазинов,
  - allowlist для обычного/премиум магазина,
  - баллы пользователей,
  - товары и варианты (номиналы).

## Уведомления в Telegram

1. Создайте бота через `@BotFather` и получите токен.
2. Добавьте бота в нужную группу и дайте право отправлять сообщения.
3. Напишите любое сообщение в группу.
4. Получите `chat_id` группы:
   - через `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, или
   - через бота `@getidsbot`.
5. Заполните в `.env`:

```
TG_BOT_TOKEN=...
TG_GROUP_CHAT_ID=-1001234567890
```

## Примечания

- `tg_username` приводится к нижнему регистру и сохраняется с `@`.
- Баллы и заказы хранятся в PostgreSQL (контейнер `db`).
- Сток `пусто` = безлимитный.

## Экспорт и массовое удаление пользователей

В разделе «Доступ по tg_username и баллы пользователей»:

- **Скачать всех пользователей и баллы — Excel** выгружает `.xlsx` с колонками
  Telegram и Баллы. В файл попадает весь список без ограничения текущей страницей
  или поиском, включая ники с заранее выданным доступом (0 баллов).
- **Удалить пользователей списком** принимает до 1000 Telegram-ников, с `@` или
  без, без учёта регистра. Разделители: перенос строки, запятая, точка с
  запятой, табуляция или `|`. Вставляйте только ники, без столбца баллов и ссылок.
  Пробелы внутри ника сохраняются: такие записи должны точно совпадать с базой.
  Ники с точками поддерживаются. Имена автоматически не исправляются.
  Повторы учитываются один раз. Ошибка в списке отменяет всю операцию.
- Удаление безвозвратно удаляет аккаунты, баллы, заказы и доступы указанных ников,
  как одиночное удаление во вкладке «Работа с БД». Требуется подтверждение.
  После операции показывается число удалённых записей и не найденных ников.

### Обновление сервера

В каталоге проекта, сохранив текущий `.env` и резервную копию базы:

```bash
git pull --ff-only origin main
docker compose up -d --build web
```

Нужна пересборка `web`, поскольку добавлена библиотека для Excel. Простого
`docker compose restart` недостаточно. Миграция базы не нужна; контейнер БД и
его том остаются прежними.

### Проверки

```bash
python -m pip install -r requirements.txt pytest==8.3.5
python -m pytest -q tests
```

По умолчанию тесты используют временную SQLite-базу. Для проверки PostgreSQL
можно задать `TEST_DATABASE_URL` **только на отдельную одноразовую тестовую базу**:
тесты создают и удаляют в ней таблицы. Никогда не указывайте рабочую базу.

## Компактный каталог товаров

В админке обычный и премиум магазины показываются отдельными списками по 30
товаров на странице. Нажмите строку товара, чтобы раскрыть редактирование.
У каждого товара есть название, описание, стоимость в баллах, количество,
позиция, активность и фото. Пустое количество означает отсутствие ограничений,
0 — товар закончился. Витрины также отображают товары компактными строками.

Варианты и номиналы больше не создаются. При первом запуске обновления старые
товары с несколькими вариантами автоматически разделяются на отдельные товары
с названиями «Товар — Номинал». Цены, остатки, активность, фото и ссылки заказов
сохраняются. Повторный запуск не создаёт копий. Старые товары без вариантов
получают нулевой остаток; задайте им цену и количество перед продажей.
Товары с заказами при удалении снимаются с продажи, история заказов сохраняется.

Загрузка фото поддерживает JPG/JPEG, PNG, WebP, GIF, AVIF, HEIC/HEIF, BMP и TIFF,
до 15 МБ и 40 мегапикселей. Проверяется содержимое, а не расширение или MIME,
переданный браузером. Изображения преобразуются в JPEG/PNG с учётом ориентации
и прозрачности; у анимированных/многостраничных файлов используется первый кадр.
SVG не поддерживается. Ранее JPG и PNG были разрешены, но загрузка могла
отклоняться из-за MIME-типа; теперь подробная ошибка показывается в админке.

Перед обновлением каталога сохраните резервную копию PostgreSQL и загрузок:

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "backup-before-catalog-$(date +%Y%m%d-%H%M%S).dump"
tar -czf "uploads-before-catalog-$(date +%Y%m%d-%H%M%S).tar.gz" app/static/uploads
git pull --ff-only origin main
docker compose up -d --build web
docker compose logs --tail=50 web
```

Схема таблиц не меняется; преобразование существующих вариантов выполняется
одной транзакцией при запуске. Внутренняя таблица вариантов сохранена для
совместимости истории заказов, а старые ручки редактирования вариантов возвращают 410.
